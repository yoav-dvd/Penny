# Penny

ליבת הנדסה ראשונית לסיוע פנסיוני, עם הפרדה בין שני לקוחות ובית האב.

**מצב: אב־טיפוס על מידע מלאכותי בלבד.** אין סוכנת מוסמכת, חיבור למודל, מסד נתונים או מערכת הרשאות משתמשים. אין להזין נתונים אישיים.

## הפעלה

נדרש Node.js בגרסה 22 ומעלה. אין תלויות חיצוניות ואין צורך בהתקנה או במפתח API.

```sh
npm test
npm run benchmark:prepare -- MODEL_ID
```

הפקודה השנייה מכינה 24 בקשות בלבד; אינה שולחת אותן למודל ואינה מחייבת בתשלום.
דוחות מקומיים נוצרים בתיקיית reports: תוצאות בדיקות, גיבוב קובצי קוד ובקשות להשוואה.

## יכולת נוכחית

- אומדן שנתי של דמי ניהול מצבירה ומהפקדות, ביתרות קבועות ובשקלים.
- סף זכאות משפחתי יחיד, חיוב לכל חשבון והקצאת השפעה לכל בעלים.
- זיהוי הפסד אישי גם כאשר לבית האב יש רווח.
- חסימה בגין בדיקת השפעה חסרה, נתונים לא תקפים או הרשאה חסרה בהקשר שסיפק המארח.
- 25 בדיקות פיתוח, כולל 12 מקרים מלאכותיים.

מנוע החישוב אינו בודק בעצמו נכונות מקצועית של הצהרות ״אין השפעה״. הוא אינו מחשב מס, פרישה, זכויות וביטוח, ניוד או תחזית תשואה. אלה דורשים יכולות ומקורות נוספים. ההרשאות בקוד הן חוזה למארח עתידי, לא מערכת כניסה מאובטחת.

## אימות

הבדיקות המקוריות עברו במנוע JavaScript של כלי הפיתוח. הרצה עצמאית ב־Node וב־GitHub Actions נחשבת מאומתת רק כאשר הריצה בפועל ירוקה; אין להסיק זאת מקיום קובץ workflow. הסקריפט מפעיל גם תהליך חדש ללא היסטוריית שיחה.

מקרי הפיתוח גלויים; אינם מבחן קבלה חסוי או הוכחה ליתרון מול מודל בסיס. הכנת הבקשות נועדה לבדוק את צנרת ההשוואה. הבחינה המקצועית תשתמש במקרים חדשים ובבודק AI עצמאי.

## המשך קרוב

1. להעביר את בדיקות Node ו־GitHub Actions.
2. לאמת את כללי המוצר מול מקורות מקצועיים, ולהגדיר מקרים חדשים ותשובות צפויות בנפרד.
3. לחבר ספק מודל דרך מתאם מוגבל בתקציב, ולמדוד תוצאות בשתי תצורות.
4. להוסיף אחסון, אימות זהות והרשאות בשרת לפני כל קליטת מידע אישי.

תכנון המוצר: דפדפן דסקטופ, המלצה אחת ברורה והסבר קצר, שני תיקים אישיים ותמונה משותפת.
