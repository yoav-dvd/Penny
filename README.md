# Penny

ליבת פיתוח לשירות פנסיוני עבור שני לקוחות נפרדים ובית האב שלהם.

**גרסה 0.3.0 — מידע מלאכותי בלבד.** קיימים מנוע חישוב, רישום מקורות, מנגנון הכנת השוואה והגדרות תפקידים עם בדיקת העברת תוצרים. אין עדיין שירות ייעוץ חי, מסד נתוני לקוחות, ממשק לקוחה, אימות זהות או חיבור לספק מודל.

## הפעלה

Node.js בגרסה 22 ומעלה; ללא תלויות חיצוניות או מפתח API.

```sh
npm test
npm run team:prepare -- tanya
npm run benchmark:prepare -- MODEL_ID --as-of 2026-10-09
```

הפקודה השנייה מכינה 24 בקשות משנים עשר מקרים חדשים; היא אינה קוראת למודל. התאריך הוא תאריך ההערכה המפורש, ולא עקיפה של בדיקת עדכניות. בוחרים תאריך מתאים להרצה אמיתית ומרעננים מקורות לפי הצורך. תאריך הבדיקה האוטומטית קבוע כדי לשחזר את אותו מצב.

תיקיית reports מכילה את תוצאות הבדיקות, גיבובי הקבצים ובקשות ההשוואה. אין בה מפתח תשובות.

## רכיבים

- penny-core.mjs: אומדן שנתי מדויק באגורות לדמי ניהול מצבירה ומהפקדות, ביתרות קבועות ובשקלים. מחשב סף משפחתי ואת ההשפעה על כל בעלים.
- source-registry.mjs ו־sources/registry.json: טענות ממקורות שנקראו, עם שימוש מותר, תאריך בדיקה ומועד בדיקה מחדש; מקורות לא זמינים או לא מאומתים לעדכניות נחסמים.
- evaluation.mjs ו־evaluation/cases-v1.json: הכנת בקשות בהקשר חדש לכל מקרה, נתונים שווים בשתי תצורות, תקרת פלט ואימות מבנה תשובה והפניות.
- run.mjs: בדיקות של ארבע השכבות ושחזור בתהליך חדש. GitHub Actions מריץ את אותן פקודות.

## גבולות היכולת

מנוע דמי הניהול אינו מחשב מס, פרישה, תשואות, משיכה, ניוד, חיוב יומי או שינויים ביתרה לאורך השנה. הצהרות שאין פגיעה בזכויות, ביטוח או מס הן קלט שיש לאמת מקצועית; המנוע אינו מאמת את אמיתותן בעצמו. הרשאת גישה בקוד היא חוזה למארח עתידי, לא מערכת אבטחת משתמשים.

רישום המקורות מאמת את מדיניות השימוש ברשומה, ואינו בודק אוטומטית את האתר או את נכונות הדין. שני המקורות המאושרים תומכים בהגדרת ברוטו ובמבנה קלט מתמטי בלבד. אין להסיק מהם תנאי מוצר אישי, דין ישראלי עדכני או הסמכה מקצועית.

הצלחת בדיקות תוכנה אינה הוכחת איכות תשובות מודל. טרם הורצה השוואת מודלים. השאלות החדשות ציבוריות ומלאכותיות; מפתח ההערכה נשמר בנפרד ואינו מצורף למאגר או לבקשות.

## השלב הבא

יש לבצע את ההשוואה לפי evaluation/README.md עם גרסת מודל ותקציב מוגדרים, ולמדוד טעויות מהותיות, בהירות הצעד הבא, זמן ועלות. הפיילוט מיועד לדפדפן דסקטופ ולשני תיקים אישיים לצד המלצות משותפות.

## תפקידים והעברת עבודה

[הגדרת טניה, חלוקת האחריות וההפעלה](team/README.md). הפקודה team:prepare טוענת הגדרת תפקיד ותיק מלאכותי ושומרת הקשר מוכן; היא אינה מפעילה מודל. בדיקות תוכנה, בדיקות מקצועיות וקבלת מוצר נשמרות בנפרד. שינוי בתוכן התיק מיישן בדיקות קודמות. זהו מנגנון לפיתוח במארח מהימן, לא אימות זהות או הוכחת איכות הראיות.
